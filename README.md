# ExpenseCast

**Intelligent Expense Tracking and Financial Forecasting Using Deep Learning-Based LSTM**

A full-stack personal-finance application that tracks income, expenses, budgets,
savings goals and investments, and forecasts future spending using a trained
LSTM neural network.

---

## Stack

- **Frontend**: React + Vite + TypeScript + Tailwind CSS + TanStack Query + Recharts
- **Backend**: FastAPI + SQLAlchemy + Alembic + Pydantic
- **Auth & DB**: Supabase (PostgreSQL + Auth + Row-Level Security)
- **ML**: TensorFlow/Keras LSTM + scikit-learn baselines
- **Deployment**: Vercel (frontend) + Render/Railway (backend) + Supabase (data)

## 1. Prerequisites

- Python 3.11+
- Node.js 18+
- A free [Supabase](https://supabase.com) project (for auth + hosted Postgres)

## 2. Machine learning pipeline (run first — the backend loads its output)

```bash
cd machine-learning
pip install -r ../backend/requirements.txt   # shares the backend's ML deps
python data/generate_sample_data.py --demo
python scripts/prepare_realdata.py            # only if you have real CSVs to validate against
python scripts/preprocess.py
python scripts/train_baseline.py
python scripts/train_lstm.py
python scripts/evaluate.py
```

This produces:
- `machine-learning/models/lstm_expense_forecast.keras`
- `machine-learning/scalers/*.joblib`
- `machine-learning/models/model_metadata.json`
- `machine-learning/evaluation/*.json` and `training_history.png`

## 3. Backend setup

```bash
cd backend
python -m venv .venv
source .venv/bin/activate        # Windows PowerShell: .venv\Scripts\Activate.ps1
pip install -r requirements.txt

cp .env.example .env
# Edit .env: set SUPABASE_URL, SUPABASE_ANON_KEY, SUPABASE_SERVICE_ROLE_KEY,
# SUPABASE_JWT_SECRET (Supabase dashboard -> Project Settings -> API).
# DATABASE_URL defaults to local SQLite; point it at your Supabase Postgres
# connection string for a shared/staging database.

alembic upgrade head              # creates all tables
uvicorn app.main:app --reload --port 8000
```

Windows PowerShell equivalents:
```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
copy .env.example .env
alembic upgrade head
uvicorn app.main:app --reload --port 8000
```

API docs: http://localhost:8000/docs

## 4. Supabase setup

1. Create a project at supabase.com.
2. In the SQL editor, run `supabase/rls-policies.sql` (after your tables
   exist — either via `alembic upgrade head` against the Supabase connection
   string, or by adapting the Alembic-generated DDL into
   `supabase/migrations/`).
3. Enable Email and Google providers under Authentication -> Providers.
4. Copy the Project URL, anon key, service role key and JWT secret into
   `backend/.env` and `frontend/.env`.

## 8. Demo Mode

Demo Mode is enabled by `VITE_ENABLE_DEMO_MODE=true` (frontend) and
`ENABLE_DEMO_MODE=true` (backend). Clicking "Try Demo" on the landing page
calls `POST /api/demo/activate`, which idempotently seeds a single fixed
demo account (`demo_user_001`) with ~1,095 transactions, budgets, goals and
investments generated by
`machine-learning/data/generate_sample_data.py --demo`, then signs the
browser in anonymously via Supabase. This account is fully isolated from
every real user by user_id — Row-Level Security guarantees no real account
can ever read or write demo data and vice versa.

## Completed features

Personal & Demo Mode isolation · email/password + Google auth · onboarding ·
transaction CRUD with search/filter/sort/pagination · 22 default categories +
custom categories · rule-based auto-categorization with user-correction
learning · CSV import with flexible column mapping and duplicate detection ·
PDF statement import with confidence scoring · budgets with 50/75/90/100%
warnings · savings goals with contribution tracking · investment tracking ·
recurring-payment detection · LSTM expense forecasting (7/30/90-day) with
tiered confidence (insufficient/low/personalized) · dashboard with live
charts · financial insights · weekly/monthly/yearly reports with CSV/PDF
export · settings incl. data export and account deletion · audit logging ·
rate limiting · Row-Level Security.

## Known limitations

- The LSTM is trained on 10 synthetic users (~10k transactions); accuracy on
  truly novel spending patterns (see the real-Kaggle-data out-of-distribution
  evaluation in `machine-learning/evaluation/final_evaluation_report.json`)
  is meaningfully worse than on the synthetic test set — expected given the
  small, single-population training set, and disclosed rather than hidden.
- PDF statement parsing uses heuristic regex extraction; real-world bank PDF
  layouts vary enormously, so confidence scoring and manual review are
  essential rather than optional.
- The in-memory pending-import cache (`_PENDING_IMPORTS` in
  `import_routes.py`) is per-process; a multi-worker production deployment
  should move this to Redis.
- OCR fallback for scanned PDFs requires optionally installing
  `pytesseract` + `pdf2image`; without them, scanned PDFs report
  `extraction_method: "ocr_unavailable"` rather than silently failing.
